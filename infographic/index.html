Backend explained

Two sources, two answers. Which one is right?

The KnowledgePulse backend reads raw documents, finds facts that contradict each other, ranks the contradictions by business impact, asks the right expert, and stores the verified answer with its provenance.

All data on this page is fictional (IKEA Belgium test documents) Document excerpts stay in Dutch, as in the source files No server needed: every value comes from a real scan, saved statically

1 · The Sentinel pipeline

From a file on disk to a scored conflict

One worked example flows through every step: the bicycle allowance at IKEA Belgium. Three documents give three different amounts. Use the buttons, your arrow keys, or press play.

2 · Extraction

Two extractors, one rule: prove it from the document

Facts are found by regular expressions or by an LLM. The LLM only reads text. Whether values conflict, who the expert is and how urgent it is are decided by plain code.

Regex deterministic · offline

A pattern per source wording, stored in detection_rules.json. The offline demo fallback and what the tests run on.

€\s*(?P<value>\d+,\d+) per (?:gereden )?kilometer

LLM flexible · needs a key

Only a plain-English topic description is needed. Each document is read in parallel, up to 20,000 characters, at temperature 0.

"The bicycle commuting allowance per kilometre in EUR
 for IKEA Belgium employees ... Value is the amount per
 km, e.g. 0,35."

extractor=auto uses the LLM when a key is configured and falls back to regex per document if a call fails. extractor=llm is strict and reports the error instead.

Grounding lab: try to fool the checker

Every fact from the LLM must come with a quote. The backend accepts it only if the quote exists verbatim in the document, contains the value, and the value parses. These are the same checks the backend runs.

3 · Priority

Which conflict gets attention first?

Priority is client tier × open tickets (48 h) × severity with severity worth 10 (high), 6 (medium) or 3 (low). Move the sliders to see where a new conflict would land among the eleven found by the real scan.

4 · Outreach triggers (API only)

Ask the expert at a dead moment

Two endpoints pick the top open conflict for an expert. There is no user interface here and no real telephony: a call is only queued and logged.

5 · Resolve

The expert answers, and the answer keeps its provenance

Only the assigned expert may resolve a conflict. The result is a VerifiedKnowledge record: who, when, through which channel, and what it replaced. A resolved conflict is never reopened by a later scan.

Response

7 · Safeguards

  
What keeps the process trustworthy

  

    
Grounded facts
An LLM fact without a verbatim quote in the source is rejected and counted.

    
Model never decides
Comparison, routing and scoring are deterministic code. The model only reads.

    
Untrusted documents
The prompt marks every document as data and tells the model to ignore instructions inside it.

    
Real excerpts
The text shown to the expert is taken from the real file, never written by the model.

    
Sources stay untouched
The backend only reads the delivered files. Each conflict keeps the original location of its sources.

    
Secrets stay local
The API key lives in a git-ignored .env and is never logged or returned.

    
Resilient scan
A missing or malformed file is reported and does not stop the scan. Re-scans are idempotent.

    
Honest limits
In-memory state, simulated expert identity, no real telephony. Context such as country or date range is left to the expert.
